# v1.5.0 Development Log

## 주요 변경

### Danbooru 태그 데이터 전면 갱신

- 공식 API의 태그 1,809,307건, 별칭 64,576건, implication 55,664건을 전체 동기화하고 무결성을 검증했다.
- 앱 자동완성 자산을 중복 없는 최신 태그 300,000개와 구버전 호환 태그 21,288개로 갱신하고 meta category와 활성 별칭 31,836개를 추가했다.
- 기존 label 규칙과 바이너리 category 코드를 유지하며, 태그 ID·원본 이름·category·count·deprecated 상태·생성/갱신 시각을 정적 원본에 보존한다.
- 통합·개명된 예전 태그를 입력해도 정식 canonical 태그가 자동완성되도록 별칭 검색을 연결했다. 별칭 데이터는 앱 시작 시가 아니라 실제 태그 검색 또는 prompt tag 검증 시에만 지연 로드하고, implication은 동기화 스테이징에 보존하며 prompt를 자동 확장하지 않는다.
- 이전 배포 목록에서 빠졌던 고유 태그 21,305개와 label 교정으로 30만 경계에서 추가 이탈한 `pink crown`을 호환 원본으로 보존한다. 이 중 21,288개는 최신 태그와 병행하고, `^_^`, `>_<`, `@_@`처럼 밑줄 자체가 의미인 18개는 잘못된 공백 표기 대신 원래 label을 사용한다. 누락 목록과 겹치는 alias 6,001개만 구버전 label과 canonical을 모두 추천하며, 전체 alias를 별도 태그로 복제하지 않는다.

## 안정성 및 유지보수

- 전체/증분/dry-run 동기화, 중단 재개, 순차 요청과 재시도, 트랜잭션 스테이징, 적용 전 백업과 검증을 지원하는 재사용 업데이트 도구를 추가했다.
- 사용자 저장 키·DB·schema·이미지·설정은 변경하지 않았다. 동기화 캐시와 백업은 개발용 `.tag-sync`에만 저장된다.
- 정적 JSON과 런타임 바이너리의 태그·count·category·alias 일치를 자동 검증한다.
