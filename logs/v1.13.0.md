# v1.13.0 개발 로그

## 모바일 경고 및 업데이트 공지

- 모바일 연결창에 아직 실험 단계이고 보안·안정성 검증이 완료되지 않았으므로 주의해서 사용해야 한다는 경고를 추가했다. 업데이트 공지는 모바일 원격 기능, 라이브러리 기본 진입 위치, 단부루 위키 캐릭터 추출과 업로드 메타데이터 제거·실패 차단으로 최신화하고 개발판·배포판 공지 ID를 함께 갱신했다. 기존 확인 상태의 저장 구조와 사용자 데이터는 변경하지 않는다.
- 연결창은 경고와 QR 표시가 긴 경우에도 스크롤할 수 있다. 3개 언어 렌더링, 이전 공지를 확인한 사용자의 새 공지 표시, 확인 후 재표시 억제, 개발판/배포판 ID 분리와 확인 전 자동 저장 없음 및 기존 원격 런타임 검사를 통과했다. 격리된 브라우저에서 합성 QR과 실제 production CSS를 사용한 3개 언어×3개 화면 폭의 경고/공지 배치 검사도 통과했다. build는 통과했고 lint는 기존 ESLint 설정 누락으로 실패했다. 실제 앱 버전은 1.12.0이며 릴리즈는 진행하지 않았다.

## 업로드 메타데이터 제거 및 실패 차단

- WebP로 바꿀 때 일반 EXIF가 없어져도 알파 픽셀에 숨은 프롬프트가 남는 문제를 실제 인코딩 결과로 재현했다. 제거 옵션이 PNG 경로에만 반영되던 분기를 고쳐 PNG·JPEG·WebP의 직접/일괄 업로드가 같은 제거 정책을 사용하도록 했다.
- 제거 후 최종 이미지의 일반 메타데이터와 숨은 프롬프트 signature를 직접 검사한다. 정보가 남거나 파일·검사가 실패하면 해당 이미지의 업로드·저장을 중단하고 일괄 작업도 다음 이미지로 넘어가지 않는다. 이미 앞서 업로드한 이미지는 유지되며, 이전 업로드 객체를 자동 삭제하지 않는다. 검사할 수 없는 결과를 성공으로 처리하지 않는다.
- 사용자 승인: 2026-10-05 공통 업로드 처리 수정과 최종 결과 검사 브레이크를 요청받아 진행했다. 로컬 원본·프리셋·DB/key/schema·저장 경로는 바꾸지 않으며 migration은 없다. 제거된 업로드본의 프롬프트는 복구할 수 없지만 원본은 보존한다. 실패 시 새 업로드를 막고 코드 변경을 되돌릴 수 있으며 기존 파일을 복원할 필요가 없다. 제거 OFF의 PNG 원본 통과와 기존 일반 변환을 유지하고 WebP 압축 방식·품질값은 변경하지 않는다.
- PNG·JPEG·WebP 사이 9개 포맷 조합을 압축/비압축 stealth 두 형식으로 검사했다. 실제 인코더 결과에 metadata를 남기는 실패를 주입해 두 업로드 화면에서 전송 중단과 후속 이미지 차단도 검증했다. PNG 동일 포맷 제거의 RGB 보존 검사와 기존 내보내기 기본 설정 검사도 통과했다. 실제 앱 버전은 1.12.0으로 유지한다.
- AGENTS.md에 여러 선택지가 같은 기능을 제공할 때 모든 호출 경로·옵션·검증·실패 정책을 함께 확인하고 최종 결과물 검사를 해야 한다는 규칙을 추가했다.
- 검증: production build, 최종 이미지/일괄 중단 검사, 기존 PNG 제거·내보내기 기본 설정·단축키 검사를 통과했다. 가로/세로 및 동일 포맷 결과도 확인했다. lint는 기존 ESLint 설정 파일 누락으로 실행 실패했다. 실제 사용자 이미지·R2 객체를 수정하지 않고 격리된 합성 이미지와 모의 전송으로 검사했으며, 실제 설치판·R2 통합 확인은 남아 있다.

## 단부루 위키 캐릭터 추출

- 웹뷰의 일반 프롬프트 복사 버튼을 아이콘으로 바꾸고 옆에 캐릭터 추출 버튼을 추가했다. 설정창은 일반 복사와 캐릭터 추출 탭으로 나뉜다.
- 사용자 확인 결과, 추출한 캐릭터는 별도 프리셋 목록이 아니라 현재 캐릭터 프롬프트 화면에 추가되어야 한다. 기존 프리셋 목록은 과거 데이터가 다수 남아 있음을 확인했지만 사용자가 접근을 원하지 않아 잠시 연결했던 버튼을 제거했다. 원본 프리셋은 삭제·이동하지 않았다. 이 숨겨진 목록과 캐릭터 삭제가 프리셋을 삭제하지 않는 사실은 회귀 기록에 남겼다.
- 현재 캐릭터 위키의 기본 태그와 Appearance·Skins 안의 실제 캐릭터 위키 링크를 수집한다. UMP45 위키처럼 두 구역이 별도 제목이면 각각 읽는다. 없는 위키·다른 종류의 태그·외부 링크·중복 링크는 제외하며, 내장 태그 DB의 정확 일치 캐릭터 태그 중 게시물 수가 설정값 이상인 항목만 기존 캐릭터 프롬프트 화면에 새 캐릭터로 추가한다. 기본 기준은 100개다.
- 밑줄을 공백으로 바꾸고 선택적으로 대표 게시물 태그에서 성별을 읽어 `girl, 캐릭터 태그` 또는 `boy, 캐릭터 태그`를 만든다. 이 전체 프롬프트를 새 캐릭터의 이름과 프롬프트로 사용한다. 여러 인물·성별 변경·조회 실패 등 불명확한 경우 성별을 추측하지 않고 결과에 미확인 수를 알린다. 대표 이미지는 저장하지 않는다.
- 데이터 변경 승인: 2026-09-29 사용자 승인 후, 저장 대상을 별도 프리셋에서 기존 캐릭터 목록으로 변경하는 추가 승인을 받았다. 새 캐릭터는 비활성 상태로만 추가한다. 기존 캐릭터·프리셋의 내용과 ID는 수정·덮어쓰기·이동·삭제하지 않는다. DB/key/schema 변경·migration은 없으며, 테스트 전용 데이터에서 기존 내용·ID와 재수화를 검증했다. 새로 추가된 캐릭터만 기존 화면에서 개별 삭제해 되돌릴 수 있으며 이전 프리셋 데이터는 그대로 유지한다.
- 첨부 미쿠 위키에서 후보 10개, 기본 기준 통과 8개를 확인했다. 링크 범위·위키 유효성·count 경계·성별 불명확성·중복 추출·높은 기준값 제외·3개 언어/창 폭 설정창 검사를 추가했다. 실제 앱 버전은 1.12.0으로 유지한다.
- 403 보고 후 조회 경계를 수정했다. 별도 HTTP 클라이언트가 열린 웹뷰의 세션 없이 위키를 다시 요청하던 흐름을 제거했다. 첫 추출은 현재 웹뷰 문서를 직접 읽고, 추가 위키·대표 게시물은 같은 웹뷰 세션으로 조회한다. 실제 접근 거절은 오류로 유지하며 재시도·인증 우회를 하지 않는다. 저장 형식과 기존 데이터는 변경하지 않는다.
- 검증: production build, Rust 웹뷰 검사, 기존 단축키 검사와 추출 DOM/UI 검사를 통과했다. 쿠키 없이 403을 반환하는 모의 서버에서 웹뷰 세션 조회 성공, 현재 문서 재요청 없음, 타 origin 거절과 실제 403 오류 전달을 검증했다. lint는 기존 ESLint 설정 파일 누락으로 실행되지 않았다. 실제 단부루 서버·설치 앱에서의 재검증은 남아 있으며 UI 통합 검사는 첨부 HTML·모의 게시물 응답과 실제 내장 태그 DB를 사용했다.

## 모바일 원격 생성 초기 테스트

### 모바일 편집 도구와 선택적 앱 반영

- 모바일 캐릭터 도구를 전체 화면 카드 편집기로 확장했다. 저장 이름의 변형 구분 해시·번호는 목록과 이름 입력창에 표시하지 않고, 이름을 바꾸어도 내부 식별 접미사는 유지한다. 씬의 캐릭터 선택 목록에도 표시 이름을 적용했다.
- 캐릭터의 Base/Negative·의상 프롬프트, 각 프롬프트 사용 여부, 활성화와 현재 해상도 비율의 그리드/자유 위치를 웹에서 편집한다. 기존 캐릭터 ID·저장 key/schema는 바꾸지 않고, 앱 반영은 기존 명시적 선택·revision 검사·실패 복원 경로를 따른다. 이름 변형 보존, 입력 검증, 원격 적용·복원 및 앱·웹 빌드를 확인했다. 실제 휴대폰 화면과 실행 중 PC 앱의 왕복 확인은 남아 있다.
- 메인 프롬프트 영역 하단에 이미지 참조·캐릭터·조각 도구를 추가했다. 기존 항목의 사용 여부와 프롬프트·참조 강도 등을 편집하고 휴대폰에서 새 항목을 추가할 수 있다. 새 참조 업로드는 현재 암호문 명령 크기 제한에 맞춰 PNG/JPEG/WebP 740KB 이하로 제한하며 초과·읽기·저장 실패를 알린다. 조각 순차 선택은 웹 생성 전용 카운터를 사용해 PC 카운터를 변경하지 않는다.
- 씬 목록의 `+`로 새 씬을 만들고 이름·해상도·긍정/부정 프롬프트·다인 씬·NPC를 편집하고 예약할 수 있다. 웹 씬의 목록 썸네일과 상세 격자는 웹에서 생성하여 받은 이미지로만 구성한다. PC에 이미 저장된 이미지는 읽지 않으며 재진입 때 임시 이미지 URL을 재사용하고 히스토리에서 해제한 URL은 썸네일에서도 제거한다.
- 기본은 웹 전용 편집이다. 설정의 ‘웹 변경을 앱에도 적용’을 켜면 생성 요청 시 해당 편집을 PC에 저장하며, 별도 ‘앱에 적용’ 버튼으로 생성 없이 저장할 수도 있다. 체크 상태·웹 초안은 영속화하지 않고 새로고침 시 초기화한다. 새 씬을 앱에 등록하지 않아도 생성 원본은 기존 씬 생성 저장 파이프라인으로 PC에 저장되지만 PC 씬 목록에는 추가하지 않는다.
- **데이터 변경 승인: 2026-09-26 사용자 승인.** 기존 생성·캐릭터·참조·조각·씬 store의 항목별 action을 재사용한다. 저장 key, backend, serialization, schema, migration, 기존 원본 경로·파일은 변경하지 않는다. 기존 참조 이미지 원본 교체·삭제는 허용하지 않고 새 참조만 기존 저장 흐름으로 추가한다. 새 씬·조각에는 요청별 고유 ID를 유지하여 빠른 연속 추가 충돌을 막는다.
- PC와 웹의 같은 항목이 변경되면 revision 비교로 거절한다. 저장 동안 기존 생성 잠금을 공유하며 연결 폐기·만료·PC 취소를 확인한다. 실패 시 이 작업이 쓴 값만 되돌리고 이후 PC 수정은 덮어쓰지 않는다. 조각의 원격 조건부 저장은 기존 IndexedDB transaction에서 stale 변경을 확인해 abort한다. 실패 중 새로 생성된 참조 원본·조각 내용은 자동 삭제하지 않고 복구 가능한 상태로 남긴다. 기존 데이터 migration·정리·삭제는 없으며 기능을 되돌려도 기존 항목을 읽는 계약은 유지된다.
- 앱·웹 빌드, 원격 요청·공통 생성·씬 큐 회귀 검사와 입력 allowlist·request-only 격리·PC 충돌·실패 복원·조각 transaction abort·새 씬 저장 검사를 수행했다. 합성 데이터로 390px 모바일 편집 화면을 확인했다. lint는 기존 ESLint 설정 누락으로 실행되지 않는다. 실제 휴대폰에서 새 참조 저장 및 선택적 PC 반영의 통합 확인은 추가로 필요하다. 실제 앱 버전은 1.12.0을 유지한다.

- 씬 재진입·목록 썸네일 조회에서 로컬 asset URL을 canvas로 다시 추출하던 경로를 읽기 전용 파일 API와 임시 Blob으로 변경했다. PC가 보유한 씬 이미지 경로만 읽으며 생성 파일·저장 설정·경로는 변경하지 않는다. 임시 URL은 성공·실패 모두 해제한다. 씬 목록 복귀 시 대표 이미지도 다시 조회한다. 앱과 같은 순서로 이름·해상도·예약·생성을 배치하고 Base/Negative·접기·다인 씬/NPC 조작을 프롬프트 바에 모았다. 다인 씬/NPC는 별도 편집창에서 열어 이미지 격자를 밀어내지 않는다. 파일 기반 미리보기 반복 조회와 기존 data URL 생성, 웹 편집·큐 회귀 검사 및 320px/390px 배치를 확인했다. 실제 Tauri 개발판 재시작 후 휴대폰 재진입 확인은 추가로 필요하다.

- 모바일 씬 탭에서 PC의 프리셋·씬 목록을 읽고 2열/3열 격자로 전환할 수 있다. 목록은 12개씩 읽으며 프리셋·페이지를 넘겨도 웹 예약을 유지한다. 씬을 누르면 앱처럼 상세 화면으로 전환하여 Base/Negative 프롬프트를 접거나 전환하고, 다인 씬 캐릭터 슬롯과 NPC를 편집한다. 다인 씬은 성별 자동·직접 연결, 슬롯 사용 여부, 긍정·네거티브 추가 프롬프트와 그리드/자유 위치 지정을 지원하며 두 프롬프트는 같은 대상 캐릭터에 적용한다. 최대 100장의 웹 큐를 한 번의 명령으로 실행하고, 현재 씬만 생성할 수도 있다. 완성 이미지마다 원본을 전달하고 해당 예약을 차감한다.

- Worker는 `relay.ciyu.us`만 배포 도메인으로 선언하고 기본 `workers.dev` 및 미리보기 URL 노출을 비활성화했다.
- 공개 중계 경로의 남용을 줄이기 위해 Cloudflare 연결 요청 제한, Worker의 IP별 연결 제한, 연결별 암호문 메시지 수·크기 제한을 추가했다. 제한은 암호문 내용을 열지 않고 적용하며, 동일 공인 IP를 공유하는 사용자는 서로의 연결 한도에 영향을 줄 수 있다.
- `dev` R2 버킷에 별도 웹의 정적 파일만 게시하고 `https://ciyu.us/index.html` 및 두 자산의 HTTPS 응답을 확인했다. 새 Cloudflare 계정에 중계 Worker를 배포한 뒤 `wss://relay.ciyu.us`에서 무작위 테스트 키를 사용한 양방향 암호문 왕복을 검증했다. 사용자가 개발판 QR 연결·생성·휴대폰 결과 이미지 수신에 성공했으며 PC의 지정 저장 폴더에도 같은 시간대 PNG가 생성된 것을 확인했다. 배포 설치판·다른 기기에서의 범용 검증은 아직 수행하지 않았다.

### 모바일 캐릭터 검색과 요청 절감

- 캐릭터 도구를 처음 열 때 전체 목록을 조회하지 않는다. 이름을 입력해 검색 버튼 또는 Enter를 눌렀을 때 PC가 표시 이름만 필터링해 한 페이지 12개를 전송한다. 변형 식별 해시로는 검색되지 않는다. 처음 연 카드의 상세만 별도 조회하며 같은 웹 탭의 동일 검색과 상세는 메모리에서 재사용한다. 조회 실패는 모달 안에 표시한다.
- 검색·상세 캐시는 웹 탭 메모리에만 있고 새로고침·재연결 시 사라진다. PC 사용자 데이터의 저장 구조와 기존 캐릭터 내용은 변경하지 않는다. 앱에 편집을 적용한 뒤에는 검색 결과 캐시를 비운다.
- 서버 필터/입력 검증과 웹의 빈 초기 화면·첫 상세·반복 검색/카드 0회 재요청을 확인했다. 앱·웹 빌드는 통과했고 lint는 기존 ESLint 설정 누락으로 실행되지 않는다. 실행 중인 PC 앱을 새 코드로 재시작한 뒤 실제 휴대폰 왕복 확인은 남아 있다. 실제 앱 버전은 1.12.0을 유지한다.

### 모바일 캐릭터 카드 조작 개선

- 캐릭터 한 장이 목록의 남은 높이 전체를 차지하던 그리드 배치를 고쳐 접힌 카드는 내용 높이만 사용하고, 펼친 카드의 Base·Negative·의상·위치 지정 영역은 목록 안에서 스크롤할 수 있게 했다. 화살표로 펼침 상태를 표시한다.
- 위치 지정은 Base/Negative 어느 탭에서나 카드 하단에 두고 PC와 동일한 전체 캐릭터 공통 토글로 켜고 끈다. 웹 생성에는 요청별 값만 적용하며, 명시적 앱 반영 시에만 기존 PC 설정에 저장한다. PC에서 그사이 토글을 변경했다면 충돌로 거절한다. 새 저장 필드·key·migration은 없다.
- 원격 workspace 회귀 검사와 앱·웹 TypeScript 검사는 통과했다. 로컬 웹 페이지에서 펼친 카드의 내용 높이·스크롤, 접힌 카드 54px, Negative 탭의 위치 지정, 검색 캐시 요청 수를 확인했다. 별도 웹 빌드를 `ciyu.us/forge.web`에 배포하고 공개 페이지가 새 CSS·JS 해시를 참조하며 CSS에 `grid-auto-rows: max-content`가 포함된 것을 확인했다. 전체 앱 빌드는 실행 환경의 Vite 설정 접근 거부로 중단됐고, lint는 기존 ESLint 설정 누락으로 실행되지 않았다. 실제 휴대폰과 수정된 PC 앱의 왕복 검증은 남아 있다. 실제 앱 버전은 1.12.0을 유지한다.

### 모바일 씬 선택·예약·삭제

- 모바일 씬 목록에서 여러 씬을 선택하거나 현재 프리셋의 모든 페이지를 선택해 큐에 한 장씩 추가하고, 웹 큐 전체를 초기화할 수 있다. 최대 100장 제한을 유지하며 큐는 PC의 예약 상태에 저장하지 않는다.
- 사용자 승인(2026-09-30)에 따라 모바일에서 기존 씬 삭제를 지원한다. 새 웹 초안은 웹에서만 제거한다. PC에 저장된 씬은 ‘웹 변경을 앱에도 적용’ 선택과 삭제 확인을 거친 뒤 기존 씬 삭제 동작으로 **씬 기록만** 제거한다. 이미지 파일은 삭제·이동하지 않으며 기존 저장 key/schema와 migration은 변경하지 않는다.
- PC 씬의 전체 기록 revision을 재확인하고 저장 쓰기를 마친 뒤 저장값에서 삭제를 확인한다. 실패 시 같은 작업의 상태가 유지된 경우 원래 씬 기록을 복원한다. 기존 자동 백업은 그대로 유지하며, 이미지 파일은 원래 경로에 남는다. 기능을 되돌려도 기존 씬 저장 구조를 그대로 읽는다.
- 앱·웹 빌드와 원격 명령·씬 큐·웹 전체 페이지 선택/삭제 회귀 검사를 통과했다. lint는 기존 ESLint 설정 파일 누락으로 실행되지 않았다. 실제 휴대폰–새 PC 개발판의 삭제 왕복 검증은 남아 있다. 실제 앱 버전은 1.12.0으로 유지한다.

### 모바일 연결 대상 혼동 방지

- 다른 웹 탭에서 새 PC의 QR을 등록했을 때, 오래된 탭의 프롬프트·씬·캐릭터 초안이 새 PC로 전송될 수 있던 문제를 수정했다. 생성·조회·앱 반영·씬 삭제 전에 현재 탭이 데이터를 읽었던 연결과 저장된 연결의 identity를 공통 경계에서 비교한다.
- 연결이 변경되거나 해제되면 명령을 보내지 않고 편집 내용을 보관한 뒤 새로고침하도록 안내한다. 오래된 탭의 초안을 자동으로 덮거나 새 연결을 삭제하지 않는다. 같은 연결의 여러 탭은 기존 최신 sequence 갱신과 중복 요청 차단을 그대로 사용한다. 저장 schema·key·사용자 프롬프트·프리셋과 PC 파일에는 변경이 없다.
- 실제 웹 요청 진입점의 패치 전 A→B 연결을 재현하고, 8개 요청 경로의 잘못된 연결 거절·편집 내용 보존·동일 연결 정상 동작을 회귀 검사했다. 응답 대기 중 연결 교체 시 실제 암호화된 pong이 생성 명령으로 이어지지 않는 것도 확인했다. 독립 읽기 전용 후보 리뷰에서 차단할 우회·회귀를 발견하지 않았다.
- 앱·웹 빌드와 원격 관련 11개 검사 스크립트를 통과했다. 앱 빌드는 sandbox 접근 제한 후 승인된 동일 명령 재실행으로 통과했으며, lint는 기존 ESLint 설정 파일 누락으로 실행 실패했다. 수정 웹을 `ciyu.us/forge.web`에 배포했다. 이미 열린 탭은 편집 내용을 보관하고 새로고침해야 적용된다. 실제 휴대폰·서로 다른 PC의 QR 전환 통합 검증은 남아 있다. 앱 실제 버전은 1.12.0이며 데스크톱 릴리즈는 진행하지 않았다.

### 라이브러리 기본 진입 위치

- 폴더 우클릭으로 다음 라이브러리 진입 위치를 지정하거나 해제할 수 있다. 전체보기·미분류는 해당 메뉴만 표시하고 일반 폴더에서는 기존 메뉴 최하단에 추가한다. 기본 진입 위치는 테두리로 구분한다. 기본값과 설정 해제 후 위치는 전체보기다.
- 저장 설정을 읽은 뒤 첫 화면부터 지정 폴더를 표시해 전체보기 썸네일을 먼저 띄우는 동작을 피한다. 기존 메타데이터 hydrate·파일 점검·스택 탐색과 이미지 경로 정책은 변경하지 않으며 전체 초기 로딩 비용을 없애는 저장소 변경은 아니다.
- 데이터 변경 승인: 2026-10-01 사용자 승인 후 기존 `nais2-forge-library`에 선택 위치 ID 한 필드만 추가했다. 이미지·폴더·스택·ID·경로와 기존 key/backend는 보존한다. 기존 데이터의 필드 부재는 전체보기로 처리하고 migration/cleanup은 추가하지 않는다. 기존 전체 백업 흐름을 유지하며 구버전 데이터의 hydrate와 설정 저장/재수화 후 기존 항목 의미·ID·경로 보존을 테스트했다. 기능을 되돌리면 이전 저장 구조를 그대로 읽고 추가 설정만 무시한다.
- 이름 변경·이동·정렬은 기본 위치를 유지한다. 지정 폴더를 삭제하면 설정을 해제하고 다음 진입은 전체보기로 돌아간다. 현재 탐색 위치의 삭제 처리와 스택 뒤로가기는 기존 동작을 유지한다. 설정·해제·재실행·삭제 fallback·hydration 및 Sidebar 메뉴 콜백 회귀 검사를 추가했다. 실제 앱 버전은 1.12.0으로 유지한다.
- 검증: 실제 브라우저의 전체보기·미분류 단일 우클릭 메뉴, 일반 폴더의 최하단 배치, 설정·해제와 3개 언어×3개 화면 폭 검사를 통과했다. 앱 production build와 관련 단축키 검사도 통과했다. lint는 기존 ESLint 설정 파일 누락으로 실행 실패했으며 실제 설치본 재실행 검증은 남아 있다. 테스트는 메모리 저장소와 격리된 브라우저만 사용했고 실제 사용자 DB·파일은 변경하지 않았다.
